Lab 3 · BeautifulSoup in depth, Selenium and the Chrome DevTools Protocol

Some data is in the HTML the server sends: requests + BeautifulSoup are enough (and fast). Some data only appears after JavaScript, a scroll or a click: then you drive a real browser with Selenium. Today you learn to tell the two apart, to handle infinite scroll and iframes, and to use the Chrome DevTools Protocol to find the hidden API behind a page ... and go back to requests.

Before you start

Put this lab3 folder inside ESILV_LAB. In a terminal in ESILV_LAB:

uv sync                    # once (or after an update of the lab)

You also need Google Chrome. Nothing else: Selenium downloads the matching chromedriver by itself the first time (internet needed once, ~30 s).

How the projects work

The exercises are functions with raise NotImplementedError(...): read the docstring (what goes in, what comes out, examples) and replace the raise with your code. Then, in VS Code:

  • Click Run ▶ on check.py: ✅ done · ❌ wrong · ⬜ not done yet (NO internet needed).
  • When everything is ✅, click Run ▶ on main.py: the real program, on the real website.

check.py never touches the websites. For BeautifulSoup and requests, your functions receive a fake session that answers with the files of samples/. For Selenium, check.py starts a local copy of the page on your computer (http://127.0.0.1:...): the real saved HTML, plus a small script that behaves like the real one (the infinite scroll). Chrome runs your code on that copy. So every student can test as often as needed without sending one request to the shops.

The rules of this lab

  • An honest User-Agent (at the top of each exercises.py), in the browser too. Never a copied browser User-Agent, never a "stealth" plugin that hides that Chrome is automated.
  • A timeout on every request, a pause between pages, the safety limits at the top of exercises.py. A browser is heavy for the site too: block images, scroll only as far as needed.
  • Refuse the cookies when a banner asks: a robot has no reason to accept tracking.
  • Always driver.quit() (in a finally): a forgotten Chrome keeps eating memory.
  • The websites of this lab were chosen because their robots.txt allows these pages and their terms of use have no clause against robots (checked in November 2026). Before you scrape any other site, read both.
  • If you get 429 (too many requests) or a block page: stop, wait several minutes. The whole class shares one IP address.
